-------------------------------------------------------------------------------
 DESIGN DECISIONS
-------------------------------------------------------------------------------
- Compile-time feature flags everywhere (user request): each lockfile ecosystem,
  each tree-sitter grammar, each heavy subsystem behind a Cargo feature, all on
  by default. Lean builds strip what they don't need, e.g.:
      cargo build --no-default-features --features npm,pypi,rust
  Heavy deps (regex, quick-xml, tree-sitter grammars) are optional, pulled in
  only by the features that need them. Verified: npm-only builds exclude them.

- Transport = ureq (blocking, pure-Rust, NO tokio) instead of the plan's reqwest.
  Reason: CLI is blocking + thread-pool concurrent; dropping tokio keeps the
  binary small (serves the lean-build goal). Behind an HttpClient trait, swappable.

- Native tree-sitter grammar crates → NO CGO / no C toolchain (the headline win).
  .scm queries port verbatim from the Go tree.

- domain crate stays dependency-free (mirrors Go's stdlib-free internal/domain);
  the CLI owns its serde wire DTOs.

 WORKING COMMANDS  (all verified end-to-end)
-------------------------------------------------------------------------------
aegis parse <lockfile> [--json]
    Parse one lockfile → dependencies.
    Verified: real go.sum (62 deps), package-lock.json.

aegis analyze <dir> [--name --ecosystem --json]
    Walk source tree → AST (tree-sitter) + heuristics → Fingerprint →
    risk_score → verdict.
    Verified: real rest-client 1.6.13 rubygems compromise → BLOCK (score 110,
    obfuscated-payload + suspicious-url). Synthetic evil npm pkg → BLOCK, 7 signals.

aegis ci <lockfile> [--fail-on --offline --json]
    Lockfile → OSV CVE lookup (LIVE network) + EPSS + KEV enrichment → severity
    gate → exit code (0 clean / 1 findings≥threshold / 2 error).
    Verified LIVE vs api.osv.dev: lodash 4.17.4 → 10 real GHSA advisories with
    correct severities + fix versions + EPSS scores (e.g. 22%); --fail-on
    high/critical exit 1; offline exit 0.

aegis run <aegis.toml> [--json]
    CONFIG-DRIVEN PARALLEL runner. Declares [[task]] entries; the cfg drives
    which checks run per task (ast/heuristics = source scan; cve = OSV lookup).
    Two-level parallelism: independent tasks run in parallel (rayon), and each
    task's source scan also fans out across cores. `parallelism = N` sets threads.
    Verified: 3-task config → 2 source-scan BLOCKs + 1 cve task (10 live findings),
    overall FAIL, exit 1.

CONCURRENCY: rayon (all cores), NOT tokio. Async ≠ fast for a CLI; the work is
CPU-bound (tree-sitter parsing) + batch network. rayon parallelizes the scan;
blocking ureq in rayon threads handles concurrent HTTP. Smaller binary, no async
coloring. AST scan verified multi-core (253% CPU on a big tree, 16 cores avail).
